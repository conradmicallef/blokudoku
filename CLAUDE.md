# Blokudoku

Clone of Blokudoku (block puzzle mixing Tetris and Sudoku) in four flavours. Remote: `github.com/conradmicallef/blokudoku`, branch `main`.

## Layout

| Folder | What | Notes |
|---|---|---|
| `pwa/` | Vanilla JS PWA (`index.html`, `style.css`, `game.js`, `sw.js`, `manifest.json`) | Reference implementation of rules and scoring |
| `pwaauto/` | Copy of `pwa/` where a bot plays itself | Own storage keys (`blokudokuauto.*`) and cache name; manual dragging disabled |
| `ios/` | SwiftUI app (iOS 16+, iPhone only) | Project generated by XcodeGen from `ios/project.yml`; the `.xcodeproj` is not committed |
| `android/` | Kotlin + Jetpack Compose (minSdk 24) | No `gradle-wrapper.jar` committed; CI installs Gradle 8.7 |

## Rules (keep all four in sync)

- 9x9 grid, three pieces offered at a time, same 35 shapes and 7 colours in every version.
- Full rows, columns and 3x3 boxes clear (union of cells).
- Score per move: cells placed, plus `n*10*n` for `n` groups cleared, plus `(combo-1)*10`. Combo resets on a move that clears nothing.
- New set of three when all are placed; game over when no remaining piece fits anywhere.
- Drag: piece floats 70 px/pt above the finger and snaps to the nearest cell by its top-left.

## Running locally

- PWA: needs `http://localhost` (a service worker will not register from `file://`): `cd pwa && python -m http.server 8080`.
- Bump `CACHE` in `sw.js` when shipping PWA changes, or old files are served from cache.
- No local iOS or Android builds on this Windows machine. CI is the only build.

## CI (`.github/workflows/`)

- `android.yml`: builds a debug APK, uploaded as artifact `blokudoku-debug-apk`.
- `ios.yml`: XcodeGen, then build and unit tests on a simulator, unsigned.
- `testflight.yml`: manual (`workflow_dispatch`) or tag `v*`. Archives unsigned, then `xcodebuild -exportArchive` signs and uploads to TestFlight. Build number = `github.run_number`.
- Keep action versions current; Node 20 based actions are deprecated.

## TestFlight / Apple facts

- Team ID `5PW663N3RU`, bundle ID `com.conradmicallef.blokudoku`, App Store Connect app "MyBlokuDoku" (SKU `blokudoku-001`, Apple ID `6817197903`). Internal testing only; builds expire after 90 days.
- Repo secrets (never commit or print them): `ASC_KEY_ID`, `ASC_ISSUER_ID`, `ASC_KEY_P8`.
- The API key must have the **Admin** role. App Manager fails at export with "Cloud signing permission error". A role cannot be edited after creation, so a new key is needed to change it.
- The archive step must stay unsigned (`CODE_SIGNING_ALLOWED=NO`). Signing it needs a development profile, which needs a registered device, and the team has none.
- iPhone-only (`TARGETED_DEVICE_FAMILY: "1"`), otherwise Apple requires iPad orientation support.
- The App Store Connect listing icon stays a placeholder until a build is attached to the version; TestFlight and the home screen use the icon from the build.

## Gotchas

- **iOS drag layout:** board and tray positions are computed from fixed heights in `ContentView.swift` (`topPad`, `headerH`, `messageH`, `gap`). An earlier version measured the board with a SwiftUI preference, which never delivered a usable frame, so previews vanished and drops landed in wrong cells. If the header, message row or spacing changes, update those constants; the drag maths depends on them.
- Line endings: Windows converts LF to CRLF on commit; the warnings are harmless.
- Heredocs with quotes in the Bash tool can fail to parse here; write files with the Write tool.
- Android and iOS code has only been built in CI, never run on an emulator by us; the iOS build has been tested on a real iPhone via TestFlight.
